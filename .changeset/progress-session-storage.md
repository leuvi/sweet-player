**播放进度改用 sessionStorage 存储，并大幅提升记录精度。**

**存储位置调整：**

| | 存在哪 | 保留多久 |
|---|---|---|
| 偏好（音量 / 静音 / 倍速） | `localStorage` | 长期保留，跨标签页、跨会话 |
| 播放进度 | `sessionStorage`（原 `localStorage`） | 仅刷新有效，关闭标签页即清除 |

需要进度在关闭标签页后依然保留，或要做多端同步，请使用 1.3.0 的 `onSaveProgress` + `player.restore()` 存到自己的后端。

**存储结构：** 进度从「每个视频一个键」改为单键存储全部记录（`{ [id]: { t, at } }`），看再多视频也不会往存储里堆条目。超过 100 条时按最后写入时间淘汰最旧的。首次读取时会清除 `localStorage` 中旧版本残留的 `sweet-player:progress:*` 键。

**记录时机补全：** 此前只有播放中每 5 秒的定时轮询和 `pause` / `ended` / `destroy()`，拖动进度条或快进快退后立即刷新页面会丢失这次跳转。现新增：

- `seeked` —— 跳转是用户明确的"从这里看"，立即记录（防抖 1 秒，合并方向键连点）
- `pagehide` —— 刷新页面时 `destroy()` 通常不会被调用，这里兜底立即落盘
- `pause` / `ended` 改为立即写入，不再等待防抖

localStorage 与后端回调两条路径现在共用同一套写入队列，节流与 `flush` 行为一致。
